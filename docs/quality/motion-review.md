# 连续动画衔接修正

2026-10-05。针对“没有连贯的动态过程，步骤衔接生硬”的反馈，替换连续模式的主要画面；分段模式继续使用同一计算轨迹的关键帧。

## 问题与修正

原全过程每次换帧都会替换两张张量卡片，并让光点回到局部起点。原理动画则是静态阶段列表加移动进度点。这些画面虽然使用连续时钟，视觉上仍是分段播放。

- 全过程使用固定的输入、网络、预测、反馈回路。每个请求的数据载体保持 DOM 身份，使用共享切线的三次曲线经过算子、层间回路和输出反馈；暂停、变速、拖动由同一时钟驱动。
- 批请求分别保留位置、通道表示和所携带的 Token。另一个请求到达、采样或结束时，等待中的请求保持自己的数据。新 Token 保留到该请求的下一次 Embedding。
- 投影分支、通道旋转、因果权重、递归矩阵、FFN 门控和 MoE 分流/合并在同一工作区连续变化。模块标签放在通路外，避免移动载体遮挡；共享专家有独立分支。
- 29 个原理的连续场景采用持续存在的对象与几何变化，包含旋转、张量变形、专家路由、缓存写入、队列入槽、量化、回滚、图执行和观测窗口等不同编排。精确关键帧数据与公式折叠保存。
- 手机上的原理图使用局部横向滚动，避免将标签缩到约 4 像素。全过程同样保留可阅读的画布；页面不产生横向溢出。

动画对位置、形状和颜色插值，教学数值仍在计算事件处提交。网络层顺序、请求状态、采样与释放逻辑保持原计算轨迹；动画时间不代表 GPU 耗时。
